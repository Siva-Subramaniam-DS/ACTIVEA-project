a. A codebase A piece of software that you will design, implement, test and run 
individually. This is worth 20% of the module mark. You will import existing 
libraries to implement your software’s  core functionality , and you will write 
original code whilst completing the coursework tasks. Make sure your code is 
syntactically and semantically correct (compiles, runs, and generates a meal 
plan that meets the requirements set out in the tasks’ description). Add 
comments to explain the logic implemented in ever y method and class. Pay

simpler classes and methods. Write appropriate unit tests.

readership. Include in your report (1) the technical insights necessary for 
comprehending the codebase, (2) the experimental setup and results obtained 
whilst completing the coursework tasks, and (3) the critical analysis of the

exercise sessions. An exercise session is a set of physical activities that a person

Exercise sessions are evaluated using measurable exercise intensity metrics 
components: 
• Metabolic Expenditure Rate (MET): a simple, practical, and easy way for 
expressing the energy cost of physical activities as a multiple of the resting 
metabolic rate1.  
• Target Rate of Perceived Exertion (RPE): the planned level of perceived effort—
expressed on an established RPE scale—that an individual should aim to reach 
during an exercise session to achieve the intended training intensity 
• Target Heart Rate (HR): the planned heart‑rate range, expressed as a percentage 
of maximum heart rate that a person should reach during exercise to achieve a 
specific intensity level, such as the moderate zone (64–76% MHR) or vigorous 
zone (77–93% MHR). 
These are all known exercise-science metrics and can be sourced from reputable 
databases and publications. 
Fitness domains —such as cardiovascular fitness, strength, mobility, agility, balance 
and functional movement— are added to the exercise-science based metrics, as 
they provide a practical way to describe the different qualities an exercise develops 
so they help structure planning and comparison even though they are classifications 
rather than formal exercise-science metrics: 
• Cardiovascular Fitness (CV): the ability to sustain activity through efficient 
heart-lung oxygen delivery.  
• Strength Development (ST): the ability of muscles to generate maximal or high 
levels of force.  
• Muscular Endurance (ME): the ability of muscles to perform repeated efforts or 
maintain contractions over time.

The core version of the algorithm suggests one ideal session, i.e., a combination of 
items from a given set of available activities that provides optimal exercise quality 
within the healthy caloric expenditure range. In other words, the algorithm’s job is to 
find the healthiest session out of all possible combinations of activities from a given 
set. 
What makes a session healthy, depends on the fitness level and the target of the 
individual. The general recommendation is to plan mixed exercise sessions for 
burning 300-600 calories. For more precise targets, the following recommendations 
are made:  
• for general health  200–400 calories/session consisting of  light-to-moderate 
mixed sessions (such as walking, strength, mobility) 
• for fitness improvement, 300–500 calories/session 
(Moderate cardio, strength circuits) and  
• for weight loss or higher-intensity training, 400–600 calories/session (such as 
vigorous cardio, interval training, or heavy mixed sessions). 
It is also expected that a healthy session includes adequate fitness domain support. 
 
Core tasks (up to 69 marks) 
Develop a basic version of ACTIVEA that evolves the combination of activities for one 
session, i.e., suggests the exercise plan for one session . To do this, complete the 
following tasks: 
1. Data setup. Compile the set of possible activities to make up the session  and 
complete the exercise quality table for each. Separate training data from testing 
data.  
2. Algorithm setup. Choose the type of evolutionary algorithm you will be 
implementing: Genetic Algorithm, Genetic Programming, Evolutionary 
Strategies, etc. Select the genetic operators (crossover, mutation, 
reproduction, etc.) and configure them to match th e chosen chromosomal 
representation (linear, hierarchical, graph, etc.). Define the fitness function,

i.e., define a mathematical equation that captures the part of the overview 
explaining what makes a healthy exercise session (consult reliable exercise -

and ranges for MET, target RPE, target HR and fitness domains).  Choose the 
selection operator and define the termination criteria. Make notes of the 
rationale behind your choices (citing supporting evidence from lecture content 
and background reading). 
3. Algorithm implementation. Write the ACTIVEA code in accordance with the 
setup completed in the previous task. You may do this from scratch or by 
importing and customising a pre-existing library (DEAP, GPLearn, etc.). Run the 
core ACTIVEA algorithm and record the experimental results alongside your 
interpretation. Make notes of the implementation details to document the 
technical aspects of your code. 
4. Nature-inspired optimisation. Select one nature-inspired algorithm out of those 
discussed in week 3, retrieve a publicly available implementation of that 
algorithm and run it on the same data used to train and test ACTIVEA. Compare 
the results against those generated by the ACTIVEA algorithm completed in the 
previous task. Make notes capturing your experimental insights regarding the 
likely causes of the differences between the exercise session  
recommendations produced by running the nature -inspired algorithm and  
ACTIVEA, respectively.  
5. Parameter management. Run systematic experiments to fine -tune ACTIVEA 
parameters: population size, number of generations, genetic operator and 
selection probabilities, etc. Follow the procedure outlined in the relevant 
practical (week 4). Make notes of the experimental setup, results and analysis. 
6.  Diversity analysis. Enhance the ACTIVEA algorithm implemented in task 3 by 
adding one diversity preservation technique out of those discussed in week 4. 
Run the original version of ACTIVEA against the enhanced one and compare the 
results. Make notes to document your additional code and capture your 
experimental insights regarding the likely causes of the differences in the two 
exercise session recommendations. 
 
Advanced tasks (70+ marks)  
After completing all core tasks (1 through to 6), perform two of the following advanced 
tasks. 
7. Improve the ACTIVEA algorithm by enhancing one of its genetic operators. 
Specifically, implement a bespoke crossover or mutation operator that 
improves the algorithm’s chances of identifying the optimal physical activity  
recommendation in as computationally efficient a manner as possible. Run

8. Improve the ACTIVEA algorithm by enhancing its fitness function to cater to 
exercise preferences from the seven exercise domains. Specifically, extend the 
fitness function formula defined in core task 2 to penalise sessions that contain

9. Improve the ACTIVEA algorithm such that it recommends several exercise

document your additional code and capture your experimental insights.
